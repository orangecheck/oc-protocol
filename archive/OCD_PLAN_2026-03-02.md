# OrangeCheck Delegation (OCD) — Implementation Plan

**Date:** 2026-03-02
**Status:** Active
**Goal:** Extend OCP into the foundational agent identity and delegation credential layer
for multi-agent AI systems.

Reference research: `AGENT_DELEGATION_GAP_ANALYSIS.md`

---

## What We're Building

OCP v0 already has the right cryptographic spine — secp256k1 signing, content-addressed
IDs, Nostr publishing, offline verifiability, Bitcoin economic accountability. It is
missing the delegation chain model required for multi-agent systems.

We are adding a second credential type on top of OCP called **OrangeCheck Delegation (OCD)**:

- **OCP attestation** → proves an agent's identity + economic stake
- **OCD credential** → proves chain-of-authority from human principal to agent

These compose. Both use the same primitives. Neither breaks the other.

## New Credential Format

### Canonical Message

```
orangecheck-delegation
issuer: <agent_id | "root:nostr:npub1..." | "root:did:method:id">
subject: <agent_id | nostr:npub1... | did:method:id>
human_principal: <nostr:npub1... | did:method:id | btc:<address>>
capabilities: <comma-sep capability strings, sorted lexicographically>
task_scope: <utf8 string, ≤256 bytes>
max_depth: <non-negative integer>
current_depth: <non-negative integer>
budget_sats: <non-negative integer | "unlimited">
proof: <parent_delegation_id | "none">
nonce: <32 lowercase hex>
issued_at: <ISO8601 UTC Z>
expires: <ISO8601 UTC Z>
ack: I authorize this delegation under human principal oversight.
[optional extensions: sorted lexicographically]
```

`delegation_id = SHA-256(canonical_delegation_message)` — same derivation as OCP.

### Chain Invariants (Verifiers MUST Enforce)

- `capabilities ⊆ parent.capabilities`
- `budget_sats ≤ parent.budget_sats`
- `expires ≤ parent.expires`
- `max_depth < parent.max_depth`
- `human_principal == parent.human_principal` throughout chain
- `current_depth == parent.current_depth + 1`
- `proof != "none"` unless issuer is a root credential signed by a human

### New Nostr Event Kinds

**kind 30079** — OCD delegation credential (parameterized replaceable by `ocd:<delegation_id>`)

```json
{
  "kind": 30079,
  "tags": [
    ["d",        "ocd:<delegation_id>"],
    ["issuer",   "<agent_id_or_root_identity>"],
    ["subject",  "<agent_id>"],
    ["human",    "<human_principal>"],
    ["proof",    "<parent_delegation_id>"],
    ["depth",    "<current_depth>", "<max_depth>"],
    ["budget",   "<budget_sats>"],
    ["cap",      "<capability>"],
    ["expires",  "<unix_timestamp>"],
    ["v",        "<verification_url>"]
  ],
  "content": "<delegation_json_envelope>"
}
```

**kind 30080** — OCD revocation (issued by original credential issuer)

```json
{
  "kind": 30080,
  "tags": [
    ["d",          "ocd-revoke:<delegation_id>"],
    ["delegation", "<delegation_id>"],
    ["reason",     "<human-readable>"],
    ["revoked_at", "<unix_timestamp>"]
  ]
}
```

### Capability Namespace

Format: `<namespace>:<resource>[:<action>]`

Registered namespaces: `tool`, `memory`, `file`, `network`, `btc`, `agent`, `llm`,
`delegation`, `attestation`. See `registry/capabilities.md` for full list.

  - Initial namespaces: `tool`, `memory`, `file`, `network`, `btc`, `agent`, `llm`, `delegation`, `attestation`
  - Format rules and validation
  - How to propose new namespaces
- [ ] **1.3** Update `docs/oc-protocol/registry/extensions.md`
  - Register `agent:` as an official identity protocol under Core Identity Bindings
- [ ] **1.4** Update `docs/oc-protocol/NIP_ORANGECHECK.md`
  - Add kind 30079 and 30080 event definitions
  - Add delegation discovery query examples
- [ ] **1.5** Write conformance test vectors under `conformance/delegation/`
  - `tv01` — valid root → agent0 chain
  - `tv02` — valid agent0 → agent1 re-delegation (max_depth decrements)
  - `tv03` — rejected: capability escalation
  - `tv04` — rejected: budget escalation
  - `tv05` — rejected: expired credential
  - `tv06` — rejected: depth exceeded (max_depth = 0, attempts re-delegation)
  - `tv07` — rejected: human_principal changed mid-chain
  - `tv08` — rejected: revoked credential (kind 30080 exists)
  - `tv09` — valid: nostr-signed credential (scheme=nostr)

## What We Are NOT Doing (Out of Scope)

- Any LOCK protocol work
- ZK proofs for private capability sets (future work)
- On-chain budget enforcement (future opt-in extension)
- Multi-sig agent identities (future work)
- SPIFFE/SPIRE integration (separate concern, different layer)
